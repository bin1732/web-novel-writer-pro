# 市场验证协议

> 所有平台参数、签约门槛、内容规范参数必须有据可查。目标：每一条数据都能追溯到公开来源，不凭空编造。

---

## 一、数据溯源标准

本 Skill 引用的每一条平台参数必须满足以下溯源要求：

| 数据类型 | 溯源层级 | 要求 | 标注格式 |
|----------|----------|------|----------|
| 平台字数范围 | L1 官方 | 平台作者帮助中心/投稿指南 | `[源: 平台名作者帮助中心]` |
| 签约门槛 | L1 官方 | 平台官方公告/签约页面 | `[源: 平台名签约页]` |
| 内容规范参数 | L2 半官方 | 平台编辑访谈/官方社区公告 | `[源: 平台编辑公开回复/社区公告]` |
| 分成比例 | L1 官方 | 平台作者后台/合作协议模板 | `[源: 平台名作者后台]` |
| 读者偏好数据 | L3 社区 | 作者社区共识/多位签约作者验证 | `[源: 作者社区共识]` |
| 平台趋势 | L3 社区 | 多个信息源交叉验证 | `[源: 综合社区信息]` |

### 溯源层级说明

- **L1 官方**：平台官方页面，最可靠。定期检查链接有效性。
- **L2 半官方**：平台人员公开表态或官方社区公告，较可靠。
- **L3 社区**：作者社区多源验证，方向性参考，不作为精确数据依据。

## 三、参数验证方法论

### 3.1 字数范围验证

```
验证步骤：
1. 访问平台官方作者帮助中心
2. 找到"投稿要求"或"章节字数"相关页面
3. 记录官方公布的字数范围
4. 若官方未明确公布，采集3位以上该平台签约作者的近期章节字数样本
5. 取样本中位数区间作为参考值
6. 标注 [源: 官方/L3 社区采样]
```

### 3.2 签约门槛验证

```
验证步骤：
1. 访问平台签约页面/作者后台
2. 记录官方公布的签约条件（字数/质量/原创要求）
3. 若有多个签约类型（如普通签约/S级签约），分别记录
4. 交叉验证：在作者社区搜索近期签约经验帖
5. 标注 [源: 官方签约页 + 社区验证]
```

### 3.3 平台内容规范参数验证

```
验证步骤：
1. 查阅平台官方关于AI使用的公告/规则
2. 查阅平台编辑在社区/社交媒体的公开表态
3. 采集作者社区中关于内容规范的近期反馈
4. 标注"参考维度"而非"精确阈值"（避免过度承诺）
5. 添加"实际以平台最新公告为准"声明
6. 标注 [源: 平台公告/编辑公开回复/社区反馈]
```

## 四、市场反馈收集机制

### 4.1 用户使用反馈

```
用户使用本 Skill 创作后：
1. 建议用户记录投稿结果（签约成功/被拒/限流/正常）
2. 若签约成功 → 记录平台 + 题材 + 字数范围 → 验证本 Skill 参数准确性
3. 若被拒/限流 → 记录拒绝原因 → 分析是否参数需更新
4. 反馈数据存入 .blacklist/feedback.json（不自动上传，仅本地）
```

### 4.2 feedback.json 格式

```json
{
  "records": [
    {
      "date": "2026-08-04",
      "platform": "番茄",
      "genre": "都市异能",
      "result": "signed",
      "chapters_submitted": 5,
      "total_words": 12000,
      "ai_score": 32,
      "notes": "前50字钩子策略有效"
    }
  ],
  "last_updated": "2026-08-04"
}
```

### 4.3 参数修正触发条件

| 信号 | 判定 | 动作 |
|------|------|------|
| 同平台连续3次签约成功 | 参数有效 | 维持当前参数 |
| 同平台连续2次被拒（字数原因） | 字数范围可能变更 | 标记"待核验"，建议用户核实官方页面 |
| 同平台连续2次被拒（内容规范原因） | 内容规范可能趋严 | 标记"规范待核验"，建议加强自然度优化 |
| 平台发布新规则公告 | 官方变更 | 立即更新 platform-guide.md 对应条目 |

## 五、参考基准验证

本 Skill 的自然度优化引擎参数基于以下公开参考分析验证：

| 验证维度 | 验证方法 | 参考来源 |
|----------|----------|----------|
| 14类AI高频词 | 对照模板化写作公开研究 + 作者社区验证 | 公开写作研究/作者社区 |
| 7大人味技法 | 对照知名作家手稿特征 + 编辑审稿反馈 | 公开作家访谈/编辑访谈 |
| 段落变异系数阈值 | 对照爆款作品章节统计 | 爆款作品章节采样 |
| 对话占比范围 | 对照拆书分析结果 + 平台热门章节采样 | 拆书分析/热门章节采样 |
| 结尾钩子模式 | 对照爆款章节末尾模式统计 | 爆款章节末尾采样 |

**验证原则**：不照搬外部参数，而是交叉验证本 Skill 参数的合理性。若外部参数与本 Skill 冲突，以官方数据 > 社区共识 > 参考来源的优先级裁决。

## 六、版本化数据管理

### 数据变更记录

所有 platform-guide.md 的参数变更必须记录：

```markdown
| 日期 | 变更内容 | 变更原因 | 验证来源 |
|------|----------|----------|----------|
| 2026-08-04 | 初始参数 | 基于官方页面+社区验证 | 平台官方+作者社区 |
| YYYY-MM-DD | 更新XX平台字数范围 | 官方规则变更 | 平台公告URL |
```

### 数据回滚机制

若用户反馈某参数导致投稿被拒：
1. 标记该参数为"存疑"
2. 在下次核验前，输出时添加"此参数存疑，建议核实平台官方要求"
3. 核验后更新或回滚

## 七、市场验证自检清单

每次引用平台数据时，过一遍：

- [ ] 数据是否有 `[源: XX]` 标注？
- [ ] 数据是否在 `verifyCycleDays` 有效期内？
- [ ] 时效性核查：数据是否已过核对周期？超期数据需标注"待核验"
- [ ] 是否有"以平台最新公告为准"的免责声明？
- [ ] 是否避免了"100%/绝对/肯定"等过度承诺？
- [ ] 市场数据是否用趋势描述而非编造的精确数字？
