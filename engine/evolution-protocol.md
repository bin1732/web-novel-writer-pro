# 自进化协议

> 黑名单与自然度优化规则的自我进化机制。目标：让自然度优化能力随使用越来越准，而非一成不变。

---

## 一、进化触发条件

| 触发器 | 动作 | 频率 |
|--------|------|------|
| 用户反馈"这个词也被AI用" | 加入动态黑名单候选 | 实时 |
| `blacklist_manager.mjs check` 扫描命中 | 记录到 hit_log | 每次 |
| `blacklist_manager.mjs evolve` | 从 recent_scan 提取新模式 | 手动/每10章 |
| 模板化痕迹趋势连续3章恶化（`state.mjs ai-trend`） | 提示加强自然度优化 + 建议evolve | 自动 |

---

## 二、动态黑名单学习流程

```
用户文本 → check 扫描
   ├─ 命中静态库 → 记录 hit_log（已知模式）
   └─ 未命中但用户标记"这是模板化痕迹" → 加入 recent_scan
                                     ↓
                              evolve 命令触发
                                     ↓
                     去重（对比静态库+动态库）
                                     ↓
                 新词写入 dynamic.txt + 标记来源/时间
                                     ↓
                      下次 check 自动纳入扫描
```

**防误报**：动态库新增词需满足：
1. 不在静态库（避免重复）
2. 不在动态库（避免重复）
3. 长度≥2字（避免单字误伤）
4. 非常见正常词（内置白名单兜底：的/了/是/在/有/我/他/她 等）

---

## 三、误报回收机制

| 信号 | 判定 | 动作 |
|------|------|------|
| 动态库某词 hit 频率 < 全库均值 10% | 疑似误报 | 标记观察 |
| 用户主动 `remove` 某词 | 确认误报 | 移出动态库 + 加入白名单 |
| 某词连续 20 章 0 命中 | 失效规则 | 提示用户是否移除 |

---

## 四、严格度自适应

| 动态库词数 | 严格度 | 行为 |
|-----------|--------|------|
| <50 | 标准 | 正常扫描 |
| 50-99 | 较严格 | 扫描+提示用户检查是否有误添加 |
| ≥100 | 严格 | 警告：动态库过大可能误伤，建议执行 `report` 审查 |

---

## 五、趋势反馈闭环

`state.mjs ai-trend` 输出趋势后：

```
趋势 = 📉改善 → 当前自然度优化策略有效，维持
趋势 = 📈恶化 → 触发预警：
   1. 提示用户"连续3章模板化痕迹上升"
   2. 建议执行 blacklist_manager.mjs evolve
   3. 建议对恶化章节单独执行模块C润色
   4. 检查是否引入了新的AI写作模式
趋势 = ➡️稳定 → 维持，若绝对值仍>60则提示加强
```

## 六、社区同步（预留）

`blacklist_manager.mjs sync` 当前为预留接口。未来接入社区黑名单时：
- 仅同步静态库版本号，不覆盖用户动态库
- 社区词进入"候选池"，需本地 check 验证后才转正
- 同步记录写入 `community_sync.json`

---

## 七、进化报告

`blacklist_manager.mjs report` 输出：
- 静态/动态库词数 + 严格度
- TOP 10 高频命中词
- 动态库最近添加词
- 智能建议（库过少→evolve / 库过多→审查 / 命中过多→检查写作）

建议每完成 1 卷（≈30-50章）执行一次 `report` 审查自然度优化进化状态。
