# 执行层协议

> 所有模块与脚本必须遵循的执行底线。目标：任何环境下都能产出可用结果，不因工具缺失而中断。

---

## 一、环境验证前置（Pre-flight Check）

进入任何模块前，先验证环境能力，决定执行路径：

| 能力项 | 检测方式 | 具备 | 不具备 |
|--------|----------|------|--------|
| **Python** | `python3 --version` | 跑 `quality_check.py` / `adaptation_converter.py` | 降级为纯规则口头检查 |
| **Node.js** | `node --version` | 跑 `state.mjs` / `blacklist_manager.mjs` / `knowledge-filter.mjs` | 降级为手动记录状态 |
| **文件写入** | 尝试创建 `state/` | 持久化章节/伏笔/自然度数据 | 仅会话内记忆，结束时提示用户备份 |

**原则**：能力检测失败 ≠ 报错退出。一律降级到纯知识模式继续服务，仅在产出末尾标注"本次未持久化/未量化检测"。

---

## 二、三层渐进式降级（Progressive Enhancement）

```
┌──────────────────────────────────────────────┐
│ Layer 1: 自动化增强模式（Automator）            │
│  Python + Node.js 全可用                       │
│  → 脚本量化检测 + 状态持久化 + 黑名单自进化      │
├──────────────────────────────────────────────┤
│ Layer 2: CLI 基础模式                          │
│  仅一种运行时可用（Python 或 Node）             │
│  → 用可用运行时跑对应脚本，其余用规则补位        │
├──────────────────────────────────────────────┤
│ Layer 3: 纯知识模式（Knowledge Only）          │
│  无任何脚本运行时                               │
│  → 完全靠 SKILL.md + references 规则口头执行    │
│  → 质量检查用规则清单逐项口述，状态用文本记录    │
└──────────────────────────────────────────────┘
```

**降级触发**：脚本执行失败（非零退出码）→ 自动退一层；连续 2 次失败 → 直接退到 Layer 3 并告知用户。

---

## 三、脚本失败处理规则

| 场景 | 处理 |
|------|------|
| 脚本不存在 | 降级，不报错 |
| 脚本语法错误 | 记录错误，降级，继续模块主流程 |
| 脚本运行时异常（文件不存在/权限） | 捕获错误信息提示用户，降级继续 |
| 脚本输出无法解析 | 忽略脚本结果，用规则兜底 |
| 连续 2 次同类失败 | 标记该脚本"本会话不可用"，后续不再调用，全用规则 |

**铁律**：脚本只是增强，不是依赖。脚本全挂，模块仍能交付正文/报告——只是没有量化分数。

---

## 四、模块执行统一流程

所有 11 个模块（A~K）遵循：

```
1. 解析用户意图 → 匹配模块
2. 环境验证前置（见上）
3. 加载模块所需知识（见 knowledge-filter.mjs）
4. 执行模块核心逻辑
5. 自然度优化引擎介入（写前/写中/写后，视模块而定）
6. 产出交付前自检（见 anti-hallucination.md 的交付前自检）
7. 状态持久化（若可用）
8. 输出 + 标注本次执行层级（Layer 1/2/3）
```

---

## 五、输入校验与边界条件

| 模块 | 最小输入 | 不足时行为 |
|------|----------|-----------|
| A 极速创作 | 题材≥2字 | 追问补全；无方向默认"都市异能" |
| C 润色优化 | 文本≥50字 | <50字直接返回原文+提示 |
| E 风格蒸馏 | 3篇×≥2000字 | 不足则提示精度有限，用户确认后继续 |
| G 续写 | 前文≥500字 | <500字提示风格提取不准 |
| H 诊断 | 文本≥100字 | <100字提示样本过小 |

---

## 六、输出规范

- **正文模块**（A/B/F/G/I）：正文 + 自然度优化自检报告（通过/未通过 + 具体问题）
- **分析模块**（D/E/H）：结构化报告 + 可执行建议
- **工具模块**（C/J/K）：转换后产物 + 注意事项
- 所有输出末尾标注：`[执行层级: Layer X]` + `[自然度优化: 通过/未通过]`

---

## 七、超长文本处理

| 文本长度 | 策略 |
|----------|------|
| <5000字 | 单次处理 |
| 5000-20000字 | 按段落分块（每块≤3000字），逐块处理再合并 |
| >20000字 | 分章节处理，每章独立检测，最后汇总趋势 |

分块处理时保持上下文衔接：每块开头注入前块末尾 200 字作为衔接锚点。
