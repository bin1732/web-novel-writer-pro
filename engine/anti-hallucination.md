# 反幻觉层

> 防止AI编造数据、规则、平台规则。目标：说的每一句都要有依据，不确定就明说。配合市场验证协议（market-validation.md）确保数据可追溯。

---

## 一、高风险场景自检触发器

以下场景必须在输出前触发自检：

| 触发器 | 风险 | 自检动作 |
|--------|------|----------|
| **引用平台具体规则**（字数/分成/签约门槛） | 平台规则变动 | 标注"截至references最后更新日期"，建议用户去平台官网核实 |
| **引用平台内容规范参数**（如平台AI使用说明） | 规范持续调整 | 标注"2026年参考值，实际以平台最新公告为准" |
| **引用作家风格特征** | 主观判断 | 标注"基于公开作品分析，非作家本人声明" |
| **引用市场数据/榜单排名** | 数据时效性 | 不编造具体数字；用"趋势性描述"替代精确数据 |
| **承诺"100%通过平台审核"** | 过度承诺 | 禁止此说法；改为"提升写作自然度，具体以平台审核结果为准" |
| **跨媒体改编版权建议** | 规则风险 | 标注"非专业意见，建议咨询专业人士" |
| **引用平台签约率/通过率** | 数据无来源 | 禁止编造具体百分比；改为"根据社区反馈，XX平台签约门槛相对较低/较高" |
| **引用规则条文** | 规则误用风险 | 标注具体规则名称+条款号，建议用户咨询专业人士确认适用性 |

|------|------|----------|--------|------|

| 平台内容规范参数 | platform-guide.md | **高**（规范持续调整） | 🟡 中（L2半官方） | 每季度核对 |
| 平台签约门槛 | platform-guide.md | 中（规则调整） | 🟡 中（L1-L2混合） | 每半年核对 |

| 作家风格指纹 | writer-styles-expanded.md | 低 | 🟡 中（基于公开作品分析） | — |
| 2026平台趋势 | 2026-platform-trends.md | **高**（年度性） | 🟡 中（综合判断） | 次年需更新 |

> 注：platform-guide.md 记录的是平台分成**模式**（如广告分成/订阅分成），非具体分成比例数值。具体比例以平台作者后台合同为准。
| 各平台编辑关注重点 | expert-panel.md | 中（编辑更替） | 🟡 中（L2-L3混合） | 每年核对 |

### 置信度评分说明

| 置信度 | 含义 | 引用时要求 |
|--------|------|-----------|
| 🟢 高 | 有官方页面/文档支撑 | 可直接引用，标注来源 |
| 🟡 中 | 有半官方或社区多源验证 | 引用时标注"参考值，以平台最新公告为准" |
| 🔴 低 | 仅有单一来源或推断 | 必须标注"仅供参考，建议自行核实" |

**规则**：引用上述数据时，若用户追问"现在还准吗"，必须诚实回答"以平台最新公告为准，本库数据截至最后更新日期"。

## 三、事实核查协议

### 3.1 平台数据核查源

引用平台数据时，优先通过以下官方入口核验：

| 平台 | 核查入口 | 核查内容 |
|------|----------|----------|
| 番茄小说 | fanqienovel.com 作者后台 > 帮助中心 | 字数范围/签约门槛/分成比例 |
| 起点中文网 | write.qidian.com 作者专区 > 写作指南 | 章节字数/签约条件/上架标准 |
| 晋江文学城 | jjwxc.net 作者论坛 > 新手指南 | 字数要求/签约流程/审核标准 |
| 七猫免费小说 | qimao.com 作者后台 | 字数范围/签约门槛 |
| Amazon KDP | kdp.amazon.com > Help | AI声明要求/字数/分类 |
| Wattpad | writers.wattpad.com | 创作指南/社区规范 |

### 3.2 核查优先级

```
用户提问 → 是否涉及具体平台数据？
  ├─ 是 → 是否有 L1 官方源？
  │       ├─ 是 → 引用 + 标注 [源: 官方]
  │       └─ 否 → 是否有 L2 半官方源？
  │               ├─ 是 → 引用 + 标注 [源: 半官方] + "以平台公告为准"
  │               └─ 否 → 降级为 Level 3 不确定声明
  └─ 否 → 按通用知识层级处理
```

### 3.3 禁止编造的数据类型

以下数据**绝对不可编造**，若无可确认来源，必须使用 Level 3/4 声明：

| 数据类型 | 禁止编造原因 | 正确做法 |
|----------|-------------|----------|
| 平台签约率/通过率 | 无公开数据，编造误导用户 | "社区反馈签约门槛相对较低/较高" |
| 平台内容规范精确参数 | 规范持续调整 | "参考维度包括XX，建议以平台公告为准" |
| 具体作者收入数据 | 隐私+无公开来源 | 不引用具体数字 |
| 平台内部审核流程 | 非公开信息 | 仅描述用户可见的投稿流程 |
| 规则条款适用性 | 规则解释需专业人士 | 标注条款名称，建议咨询专业人士 |

## 四、不确定声明协议

当无法确认某信息时，**禁止编造**，按以下层级降级：

```
Level 1: 有references依据 → 直接引用 + 标注来源文件
Level 2: 有通用知识但无references → 引用 + 标注"通用经验，非本库数据"
Level 3: 不确定 → 明说"这一点我不确定，建议你去XX核实"
Level 4: 完全不知道 → "我没有这方面的可靠信息，不编造"
```

**铁律**：宁可说"不知道"，不编造看似合理的细节。编造一个签约门槛数字，可能导致用户投稿被拒。

### 声明模板

| 场景 | 声明模板 |
|------|----------|
| 引用平台字数范围 | "根据 platform-guide.md（截至YYYY-MM-DD更新），XX平台每章建议XXXX-XXXX字。建议以平台作者后台最新要求为准。" |
| 引用平台内容规范 | "XX平台的内容规范包括XX，此为2026年参考信息，规范持续调整，以平台最新公告为准。" |
| 引用作家风格 | "基于对XX作家公开作品的分析，其风格特征包括XX。此为分析结论，非作家本人声明。" |
| 不确定的数据 | "这一点我不确定，没有可靠的公开来源。建议你在XX平台作者后台/帮助中心核实。" |
| 规则相关建议 | "以下为基于公开信息的一般性参考，非专业意见。具体问题请咨询专业人士。" |

## 五、交付前自检清单

每次输出正文/报告前，过一遍：

- [ ] 引用的平台参数是否来自 platform-guide.md？（非编造）
- [ ] 引用的平台内容规范参数是否标注时效？
- [ ] 是否有"100%/绝对/肯定"等过度承诺？（有则改）
- [ ] 市场数据是否用了精确数字？（是且无来源则改为趋势描述）
- [ ] 跨媒体/版权建议是否标注"非专业意见"？
- [ ] 作家风格描述是否标注"基于公开作品分析"？
- [ ] 引用的数据是否标注了置信度（🟢/🟡/🔴）？
- [ ] 是否有禁编造数据类型被编造？（签约率/精确阈值/收入数据/内部流程）
- [ ] 规则相关建议是否标注"建议咨询专业人士"？

## 六、幻觉纠正协议

发现已输出内容含编造数据时：

1. **立即纠正**：明说"刚才提到的XX数据不准确，更正为..."
2. **记录教训**：在会话内标注，避免重复
3. **降级声明**：若无法确认正确值，改为Level 3/4声明
4. **追溯来源**：检查是否为references中数据过期，若是则标记"待更新"

## 七、自然度优化与反幻觉的边界

| 维度 | 自然度优化 | 反幻觉 |
|------|------|--------|
| 目标 | 让文本不像AI写的 | 让内容不编造 |
| 对象 | 文笔/句法/词表 | 数据/规则/声明 |
| 机制 | 黑名单+人味注入 | 自检+不确定声明+事实核查 |
| 验证 | quality_check.py 量化检测 | market-validation.md 溯源核查 |

两者独立运作，不可混淆：自然度优化做得好不代表内容准确；内容准确也不代表没有模板化表达。**两条线都要过**。

---

## 八、与市场验证协议的联动

反幻觉层负责"不编造"，市场验证协议（market-validation.md）负责"有依据"。两者协同：

```
输出数据时：
  ├─ 反幻觉层：是否在禁编造清单中？ → 是 → 降级声明
  ├─ 市场验证协议：是否有溯源标注？ → 否 → 补充来源
  └─ 交付前自检：置信度标注是否完整？ → 否 → 补充标注
```

**双重验证**：每条平台数据必须同时满足：
1. 反幻觉层：不在禁编造清单中 + 有不确定声明（若需要）
2. 市场验证协议：有溯源层级标注 + 在有效期内
