# ⚔️ 自然度优化引擎 · 完整规则库

> 本库是本 Skill 的**核心基础设施**，贯穿所有写作模块。
> 七大支柱：①词表级 → ②句法级 → ③段落级 → ④人味注入 → ⑤平台适配 → ⑥写作自然度自检 → ⑦叙事指纹
> 三阶段工作流：写前预防 → 写后分析 → 定向改写

---

## 自然度优化三阶段工作流（2026版）

基于2026年主流网文平台的创作趋势与读者偏好，形成以下标准操作流程：

### 阶段A：写前预防（Prompt层）

创作开始前加载自然度优化规则，从源头避免生成模式化内容。

```
创作提示词中自动注入：
├── 禁用词黑名单（从14类中按概率抽取50个注入）
├── 句式多样化约束（禁止连续3句同结构）
├── 角色口癖强制（每个角色的对话DNA）
└── 段落节奏控制（最长/最短段比>3:1）
```

### 阶段B：写后分析（统计层）

创作完成后进行多维统计分析，定位高风险段落。

| 自检维度 | 指标 | 健康值 | 警示信号 |
|----------|------|--------|----------|
| 词汇多样性(TTR) | 独特词/总词 | 0.4-0.7 | ≤0.20高风险 |
| 句长变异系数 | 标准差/均值 | ≥0.5 | <0.3句式均匀 |
| 3-gram重复率 | 短语重复比例 | <5% | >8%模板化 |
| 连接词密度 | 禁用词/300字 | ≤2 | >2机械感 |
| 标点间隔CV | 标点间距变异 | ≥0.4 | <0.3节奏过于规律 |

### 阶段C：定向改写（修复层）

仅对阶段B标红的高风险段落执行改写，不动安全段落。

```
高风险段落 → 针对性改写 → 重新评分 → 最多循环2轮
改写原则：只改特征不改内容，只动异常段不动整篇
```

## 支柱一：词表级自然度优化（14大类+替换词池）

> 每一类AI高频词都配有3-8个替换选项，随机选择避免替换后千篇一律。

### 第1类：过度逻辑连接词 — 禁用

| 禁用词 | 替换方案 |
|--------|----------|
| 首先、其次、最后、第一、第二、第三 | 直接句号另起一段，或用顿号并列 |
| 综上所述、总而言之、总的来说 | 直接删除，不要总结 |
| 由此可见、不难看出、显而易见 | 直接删除，让读者自己看出 |
| 换言之、换而言之、换句话说 | 直接删除 |

**改前**：首先，我们需要分析市场趋势。其次，要确定目标读者。最后，才能开始创作。
**改后**：分析市场趋势。确定目标读者。然后动笔。

**改前**：综上所述，这是一个值得尝试的方向。
**改后**：这个方向值得一试。（或者什么都不说，让内容自己证明）

### 第2类：绝对化表述 — 软化

| 禁用词 | 替换方案 |
|--------|----------|
| 完全、绝对、一定、必然、肯定 | 约八成、多数情况下、大部分时候、通常 |
| 所有、一切、任何 | 大多数、很多、绝大多数 |
| 从不、从未、永远不 | 很少、几乎不、极少 |
| 百分之百、毫无悬念 | 大概率、基本上、差不多 |

**改前**：这完全改变了一切。
**改后**：这件事改变了大多数人的看法。

**改前**：他绝对不可能成功。
**改后**：所有人都觉得他成不了。（用"所有人觉得"替代"绝对不可能"）

### 第3类：抽象名词堆砌 — 替换为具象描述

| 禁用 | 替换 |
|------|------|
| 价值、意义、本质、核心、关键 | 直接说具体的好处或坏处 |
| 维度、层面、角度 | 从...看，站在...立场 |
| 赋能、抓手、闭环、底层逻辑 | 直接说做了什么、怎么做的 |

**改前**：这件事的核心价值在于提升用户体验的维度。
**改后**：用户打开软件不用等那么久了。

### 第4类：模板化开头 — 直接删除

| 禁用开头 | 处理 |
|----------|------|
| 在当今...时代、随着...的发展 | 直接说事，不要时间状语 |
| 众所周知、我们都知道 | 直接说事实 |
| 在...的背景下 | 直接说发生了什么 |

**改前**：在当今AI快速发展的时代，写作方式也在发生变革。
**改后**：AI来了。写作变了。

### 第5类：总结性套话 — 删除

| 禁用词 | 处理 |
|--------|------|
| 这意味着、这说明了、这就意味着 | 删除，让读者自己理解 |
| 值得注意的是、不得不提的是 | 删除，直接说事 |
| 需要指出的是、值得关注的是 | 删除 |

**改前**：值得注意的是，他的眼神变了。
**改后**：他的眼神变了。（读者看得出来这值得注意）

### 第6类：虚假关怀 — 替换

| 禁用词 | 替换 |
|--------|------|
| 值得注意的是 | 其实、问题是、但 |
| 不得不提的是 | 说来有趣、对了 |
| 需要强调的是 | 记住一点 |

### 第7类：过度因果链 — 简化

| 禁用词 | 替换 |
|--------|------|
| 因此、所以、于是、从而、因而 | 结果、然后、或者直接句号 |
| 正因为如此、鉴于此 | 所以、就直接说结果 |
| 导致、致使、使得 | 让、逼得、搞得 |

**改前**：由于他没有及时提交方案，因此导致了项目延期，从而影响了整个团队的计划。
**改后**：他没交方案。项目延期了。整个计划被打乱。

### 第8类：假设性让步 — 替换

| 禁用 | 替换 |
|------|------|
| 虽然...但是...、诚然...不过... | 有人会说...但我亲眼见过... |
| 不可否认、我们必须承认 | 我承认、说实话 |

**改前**：虽然这个方法有缺点，但是效果不错。
**改后**：有人说这方法不行。我用过，管用。

### 第9类：数据过度精确 — 软化

| 禁用 | 替换 |
|------|------|
| 100%、百分之百、完全 | 差不多、基本上、约莫 |
| 0%、完全不、丝毫不 | 基本不、几乎没、很少 |
| 精确数字（如"87.3%的用户"） | 大多数、很多、七八成 |

### 第10类：情感标签化 — 禁止使用标签词

| 禁用标签 | 替换写法 |
|----------|----------|
| 他很感动、她很难过、他非常愤怒 | 使用身体反应替写（详见 `emotion-recipes.md` 情感描写五技法） |
| 心中涌起一股暖流、内心充满感激 | 用具体动作和细节暗示情绪 |
| 孤独、疲惫、落寞、温暖、感动 | 用感官细节替代，见 `sensory-library.md` 情绪×感官对应表 |

### 第11类：逻辑过度显式化 — 删除

| 禁用 | 处理 |
|------|------|
| 这意味着、换句话说、也就是说 | 直接删除 |
| 从某种意义上说、某种程度上 | 直接删除 |
| 这背后的逻辑是、原因是 | 让读者自己推理，或通过上下文暗示 |

### 第12类：AI高频转折词 — 减少使用

| 禁用 | 替换 |
|------|------|
| 然而、但是、可是、不过、却 | 但、可、或者不加转折，直接接下一句 |
| 与此相反、恰恰相反、与之不同 | 直接用"但"或者不转折 |

**改前**：他看起来很有信心。然而，他的手在发抖。
**改后**：他看起来很有信心。手在发抖。

### 第13类：过度比喻 — 限制使用

| 禁用 | 规则 |
|------|------|
| 像、仿佛、如同、好比、宛如、犹如 | 直接描述，不要比喻 |
| 就像...一样、正如...那般 | 除非是人物性格的一部分，否则禁用 |

**允许的例外**：自然嵌入的感官小比喻（"她笑起来像她妈"），不是陈词滥调就行。
**禁止的**：开篇天气/景物比喻 + 陈词滥调（"时间如流水"、"人生如戏"）

### 第14类：无效强调 — 删除

| 禁用 | 处理 |
|------|------|
| 真的、确实、实在、的确、其实 | 删除，靠内容本身说话 |
| 我不得不说、我必须说 | 直接说 |
| 说真的、老实说 | 直接说，不要声明 |

## 支柱二：句法级自然度优化

### 规则1：句式多样性

AI倾向使用相同句式结构（主谓宾每句一样），人为制造句式变化。

**改前**（句式重复）：
他走进房间。他看到桌子上的信。他拿起信。他打开信封。他读了起来。

**改后**（句式变化）：
他推开门。房间很暗，只有窗帘缝里透进来一线光。桌子上有封信。拿起信的时候，信封边角还带着点潮气。拆开。读。

**句型分布目标**：
- 简单句：40%（短促有力）
- 复合句：35%（展开描述）
- 疑问句：10%（制造互动感）
- 倒装/省略句：10%（打破规律）
- 排比/并列：5%（慎用，最多连续2次）

### 规则2：句长变化

AI倾向每句话长度接近，人为制造句长差异。

**改前**（句长均匀，每句15-20字）：
他沿着河堤走了很久。河水在月光下泛着银光。远处传来狗叫声。他停下来点了一根烟。烟雾在夜色中散开。他想起很多年前的事。

**改后**（句长变化，3字-40字混排）：
他沿着河堤走。走了很久。
河水在月光下泛着银光，晃得人眼睛发酸，像碎银子铺在水面上。
远处狗叫。
他停下来，点烟。打火机打了三次才着。
烟雾散在夜色里，模糊了前方的路。
想起很多年前。

**句长分布目标**：
- 短句（1-8字）：15-20%
- 中句（9-25字）：50-60%
- 长句（26-50字）：20-30%
- 超长句（50字+）：0-5%

### 规则3：连接词密度管控

**目标**：≤2个逻辑连接词/300字
**自查方法**：每300字扫描一次连接词，超过2个则删减

**示例**：
- 超标："他**然而**没有放弃，**虽然**困难重重，**但是**他坚持了下来。**因此**，**最终**他成功了。"（5个/60字 → ❌）
- 合规："他没放弃。困难很多。他坚持了下来。最后，成了。"（0个 → ✅）

### 规则4：禁用假辩证句式

| 禁用句式 | 替换 |
|----------|------|
| 虽然...但是... | 直接说观点，用具体事例支撑 |
| 诚然...不过... | 承认+反驳用具体经历（"有人这么说。我是这么看的..."） |
| 不可否认...然而... | 直接说自己的判断 |
| 一方面...另一方面... | 拆成两段，或者只说最重要的一方面 |

### 规则5：叙事视角一致性

**第三人称限知**（推荐）：全程跟随主角视角，不写主角看不到听不到的信息
**第一人称**：严格保持在"我"的所见所闻所思
**禁止**：一篇文章内切换视角（除非有明确分隔标记）

## 支柱三：段落级自然度优化

### 规则1：段落长度变异

AI倾向每段长度均匀（3-5句一段），人为制造不均匀。

**量化标准**：
- ≥3个段落>5句（长段，展开描写）
- ≥3个段落≤1句（短段，一个词也行）
- 最长段/最短段字数比 > 3:1

**目标分布**：
- 1句段（短促有力）：15-20%
- 2-3句段（推进情节）：30-40%
- 4-6句段（展开叙事）：30-40%
- 7句+段（情绪高潮）：10-15%

### 规则2：憋-释放节奏

不把事件均匀分布在每一段。先憋住（铺垫），再释放（高潮）。

**短周期（单章内）**：
```
憋(前80%)：铺垫、埋伏笔、制造期待
释放(后20%)：反转、爽点、高潮
```

**中周期（3-5章）**：
```
憋(前3章) → 小释放(第4章) → 再憋(第5章) → 大释放(第6章)
```

### 规则3：断裂式留白

在关键处突然断掉或换话题，让读者自己填空。

**技法1：说到一半换话题**
```
"我想起来了，那天——"
他没说下去。窗外有什么东西吸引了注意。
```

**技法2：用空行代替**
```
"我们分手吧。"

（空行，直接切换场景）

三个月后。
```

**技法3：一个词成段**
```
他举起剑。

沉默。

一剑。

对面的人倒下了。
```

### 规则4：废笔

AI倾向每句话都有信息量。人为加入无信息量的"废笔"（走神/闲笔/无关细节）。

**改前**（全是有效信息）：
他核对粮册，发现数目不对，立刻去查了仓库记录。

**改后**（加入废笔）：
他翻着粮册。外头那只乌鸦叫得烦人，从这棵树飞到那棵树，又飞回来。他盯着乌鸦看了会儿，才猛地看见册子上的数目不对。

**废笔密度目标**：每500字至少1处"与主线无关但增加真实感"的细节。

## 支柱四：人味注入（7个底层技法）

> 每个技法必须结合"具体情况"使用，不是机械套用。频率：每300-500字用1个技法，交替使用。

### 技法1：糙话/脏话

**核心**：适当塞口语化的糙话，让人物说话更像真人。

| 人物类型 | 糙话程度 | 示例 |
|----------|----------|------|
| 底层/市井人物 | 高 | "我操，这什么破事" |
| 军人/硬汉 | 中高 | "他妈的，又来这套" |
| 普通主角 | 中 | "靠，这下麻烦了" |
| 女性主角 | 中低 | "烦死了""什么鬼" |
| 高雅/文人 | 低 | "这...不太妙" |

**注意**：糙话是人物塑造的一部分，不是每句话都要骂。平均每500-800字用1次。

### 技法2：走神闲笔

**核心**：做正事时走神，想无关的事。

**示例**：
- "他核对粮册，外头那只乌鸦叫得烦人，他盯着看了会儿，才猛地看见数目不对"
- "写报告。写到一半想起早上吃的包子馅有点咸。接着写。"
- "她在等回复。手机屏幕暗了，她按亮，又暗了，又按亮。第十七次按亮的时候，消息来了。"

### 技法3：迟钝与记错

**核心**：反应慢、记混、事后才懂。不要所有角色都机灵得像AI。

**示例**：
- "他当时没多想。过了两天才回过味来——那句话不对劲。"
- "她的名字...叫什么来着？哦对，林晓。叫错三次才记住。"
- "他猜了三个人，前两个都猜错，第三个还是沈三随口一提他才拐过弯。"

### 技法4：碎对话

**核心**：真人说话断句、答非所问、不说完。

**改前**（完美的对话）：
"你去做什么？""我去查粮仓。""小心点。""好。"

**改后**（碎的对话）：
"你干啥去。"
"......查个东西。"
"哎你——"
"知道了知道了。"

**改前**（完美的对话）：
"你真的喜欢我吗？""当然喜欢。"
**改后**（碎/答非所问）：
"你喜欢我吗。"
"外面下雨了。"

### 技法5：自然长短混排

**核心**：长的拖，短的戳。不整齐。

**改前**（每句/段长度均匀）：
他站住了。他回头看。月亮很亮。他拔出了刀。刀在月光下闪着寒光。他的心跳得很快。

**改后**（长短混排）：
他站住了，回头看了一眼。
月亮白得晃眼。
他把手按在刀柄上，没拔，又松了。

### 技法6：不完美角色

**核心**：会怂、会贪、会嘴硬、会做蠢事。不允许完美推理机。

**改前**（完美）：
他推演三步，锁定真凶。

**改后**（不完美）：
他猜了三个人。第一个猜错。第二个也猜错。第三个还是人家随口一提他才想到。

**改前**（完美英雄）：
他毫不犹豫地挡在她面前。
**改后**（真实的反应）：
他愣了一下。脑子里闪过"关我什么事"的念头。但还是站了过去。

### 技法7：生活化脏细节

**核心**：写那些"不干净""不体面"的真实细节。

| 类型 | 示例 |
|------|------|
| 身体 | 尿憋、打嗝、放屁、鼻涕、汗味、脚臭 |
| 环境 | 苍蝇、馊味、油腻的桌面、发霉的墙角 |
| 动作 | 抠鼻屎、挠痒、剔牙、剪指甲 |
| 状态 | 吃不饱、睡不够、衣服穿了好几天没洗 |

**注意**：脏细节是人物塑造工具，不是为脏而脏。每500-1000字用1次。

## 支柱五：平台适配自然度优化

> 不同网文平台的读者偏好与风格要求不同，自然度优化策略也需要差异化。

### 番茄小说

| 维度 | 平台风格要求 | 自然度优化策略 |
|------|------|----------|
| 风格重点 | 快节奏、爽文密度、口语化程度 | 每200-300字一个爆点，保持高口语化 |
| 常见短板 | 描写过多、节奏拖沓、书面语过重 | 描写占比15-20%，对话占比40-50% |
| 对话要求 | 口语化、碎 | 使用「」直角引号，碎对话技法 |
| 字数 | 2200-2800字/章 | 严格控制在范围内 |
| 开头 | 前50字决定生死 | 冲突开场或悬念开场 |

### 起点中文网

| 维度 | 平台风格要求 | 自然度优化策略 |
|------|------|----------|
| 风格重点 | 文笔质量、设定自洽、人设稳定 | 保持文风一致性，注意前后呼应 |

## 支柱六：写作自然度自检

### 模板化写作特征参考

以下特征常见于模式化写作中，识别并修正它们有助于提升行文的自然度与个人辨识度：

| 常见特征 | 对应问题 | 写作改善方向 |
|----------|-------------|------------|
| 句式结构雷同 | 每句长度结构雷同 | 制造句长差异（3字-40字混排） |
| 用词过于"标准" | 缺乏个人语料 | 插入个人化语料：方言词/口头禅/个人习惯用词 |
| 机械逻辑连接词 | 然而/因此/此外/显然/或许密集 | 连接词≤2个/300字，主要靠内容逻辑衔接 |
| 段落过工整 | 每段起承转合、信息密度均匀 | 制造"废笔"和"断裂"，部分段落只有半句话 |
| 缺个人化表达 | 没有"这个人特有的嗓音" | 每个角色设计独特的说话方式和用词习惯 |

> **注意**：自然度优化关注的是内容质量与阅读体验本身。写作自然度的提升是持续过程，应专注于原创表达与作品质量，而非追求任何形式的指标达标。

### 句式与情感表达自检

| 自检维度 | 写作改善方向 |
|----------|------------|
| 语义连贯性过强 | 段落间可自然切换话题，模拟真人思维跳跃 |
| 句式多样性不足 | 每段检查句式变化，连续3句同一结构则重写 |
| 情感表达模式化 | 避免"感动/愤怒/悲伤"等标签词，用身体行为替代 |
| 信息密度过高 | 每300字插入1-2句"无信息量"的闲笔 |

### 通用自然度检查清单

输出前逐项检查：

```
□ 连接词密度 ≤2个/300字
□ 不使用禁用词（首先/其次/综上所述/值得注意的是/不可否认等）
□ 不使用情感标签词（感动/愤怒/悲伤/孤独/温暖等直接情绪词）
□ 不使用比喻（像/仿佛/如同等，除非是人物性格）
□ 段落长度不均匀（最长/最短比>3:1）
□ 句式有变化（不要连续3句同样结构）
□ 至少使用了3个底层人味技法（糙话/走神/记错/碎对话/长短混排/不完美/脏细节）
□ 对话使用了「」直角引号（中文模式）
□ 没有总结性结尾（禁止"这就是""总的来说"）
□ 没有假辩证句式（虽然...但是.../诚然...不过...）
□ 有至少一处情绪降调（不是全程高潮或全程平淡）
□ 有至少一处人设坠落（主角暴露弱点/犯错/自我吐槽）
□ 有"废笔"（与主线无关但增加真实感的细节）
□ 叙事视角一致（没有切换POV）
□ 结尾不是鸡汤总结（禁止"让我们一起"未来可期"等）
□ 前50字直接进入冲突或悬念（禁止天气/环境/背景开场）
```

## 支柱七：叙事指纹自然度优化

> 成熟作者会在跨章节创作中保持一致的"因果密度/句长方差/情感轨迹"——这就是叙事指纹。
> 保持叙事指纹的一致，是作品文风统一、阅读体验连贯的基础。

### 什么是叙事指纹

每个作者在写作时都会留下独特的"认知习惯模式"——叙事指纹。它包括：

| 维度 | 说明 | 成熟作者特征 | 模板化写作特征 |
|------|------|----------|--------|
| **因果密度** | 每千字埋设和回收的因果关联数 | 2-3个/千字，节奏起伏 | 4-6个/千字，密集均匀 |
| **句长方差** | 句子长度的离散程度 | 0.6-0.8，长短交替自然 | <0.3，句式过于工整 |
| **情感轨迹** | 情绪涨落的周期性 | 有波峰波谷，符合剧情节奏 | 平均情感值走平 |
| **信息密度** | 每段承载的新信息量 | 疏密交替，有张有弛 | 均匀释放，无松紧变化 |
| **逻辑跳跃度** | 段落间的因果关联间隙 | 有自然断裂感，留白 | 衔接过于平滑，无跳跃 |

### 文风一致性自检原理

以作品自身前20章的行文特征为"基线"，逐段对比后续章节。当某段落的特征偏离基线超过一定幅度时，说明文风出现漂移，需要回看修正。

```
作者基线（前20章统计得出）：
├── 因果密度均值：2.3个/千字，标准差 0.8
├── 句长方差均值：0.65，标准差 0.12
└── 情感轨迹波动幅度：3.2/10，标准差 0.9

某章节自检结果：
├── 因果密度：5.1个/千字（偏离+3.5σ）→ ❌ 需修正
├── 句长方差：0.25（偏离-3.3σ）→ ❌ 需修正
└── 情感轨迹：1.1/10（偏离-2.3σ）→ ⚠️ 提醒
```

### 叙事指纹一致性策略

**策略一：保持指纹一致**
- 同一本书内保持一致的因果密度和句长方差
- 续写前通读上一章结尾，对齐角色语调和节奏
- 避免多人分段合写的"拼接模式"——会在文风上留下裂痕

**策略二：避免均匀化**
- 模板化写作的常见问题在于**太均匀**——因果密度、句长、情感都过于"标准"
- 制造合理波动：某段因果密集，下一段就让角色闲聊
- 句长从30字突然跳到8字再跳到45字

**策略三：人工主导创作**
- 核心冲突、人物对话、情感转折 → 人工创作（形成个人风格指纹）
- 环境描写、打斗场面、过渡段落 → AI辅助润色
- 最终校验时，确保人工创作段落占全文>50%

**策略四：建立作者基线**
- 每部作品前20章建立自己的基线指纹
- 后续每10章检查一次指纹是否漂移
- 发现漂移立刻回看，修正风格

**策略五：定稿前自检**
- 对薄弱段落做定向打磨，而非全文重写
- 重点关注：对话段句长方差是否过低、情感轨迹是否走平
- 修改后逐段复检，确保文风一致而非相互割裂

### 章节文风一致性自检

文风一致性自检关注作品的连贯性与原创表达，核心三层：

| 层级 | 检查内容 | 写作改善方向 |
|------|----------|------------|
| **L1 表达一致性** | 用词、句式与作品自身风格是否一致 | 人工重写与个人风格偏离的核心段落 |
| **L2 结构多样性** | 词汇/句式/段落/情感特征是否多样 | 多样化句式，调整均匀节奏，自然跳跃 |
| **L3 原创性确认** | 内容是否原创、有无模板化套路 | 确保原创表达为主，人工创作为主 |

### 各平台创作风格偏好参考（2026年更新）

> 以下信息仅供参考，创作风格以各平台最新公告为准。

| 平台 | 风格重点 | 关键注意事项 |
|------|----------|----------|
| **番茄小说** | 对话口语化、快节奏 | 对话段不可模板化，需加入方言/口癖 |
| **起点中文** | 文笔质量、设定自洽 | 核心内容以原创表达为主 |

| **阅文系** | 区分辅助与生成 | 辅助可、生成不可 |

## 附录D：注入灵魂六法

仅做规则清洗（替换词+删连接词）效果有限。必须同时做"注入灵魂"：

### 1. 有观点
不要只报告事实——对它们做出反应。
- ❌ "实验产生了有趣的结果"
- ✅ "我真的不知道该怎么看待这件事"

### 2. 有态度
去除AI绝对中立，保留个人偏向。
- ❌ "从某种程度上说，这种方法有一定优势"
- ✅ "这方法管用。至少对我管用。"

### 3. 有瑕疵
允许句式参差、口语赘余、临时插话。
- ❌ 每句话都工整完美
- ✅ 有些句子"不顺"，像真人说话

### 4. 有跳跃
不要事事解释，相信读者能跟上。
- ❌ "因为他迟到了，所以会议推迟了。这导致了项目延期。"
- ✅ "他迟到了。会议推迟。项目延期。"

### 5. 有废笔
加入一些无关但真实的细节。
- ❌ 全是有效信息，没有废话
- ✅ "说到一半，窗外有只鸟飞过。"

### 6. 有反差
不要全程一个调子，制造情绪反差。
- ❌ 全程客观中立
- ✅ 该生气时生气，该吐槽时吐槽

## 附录F：硬门机制与回滚阈值（自然度优化质量门控）

> 基于 xt-webnovel-writing 的25项分级体系与 oh-story-claudecode 的毒句式欠账门机制。

### 三级门控体系

每项检查结果归类为以下三级：

| 级别 | 含义 | 处理要求 | 对标 |
|------|------|----------|------|
| 🔴 **回滚级** | 触发则整章退回重写 | 该章不可交付，回到大纲阶段调整 | xt-webnovel-writing 硬门 |
| 🟡 **拦截级** | 必须修复后才能继续下一章 | 当前章可修复，但下一章被阻塞 | oh-story 毒句式欠账门 |
| 🟢 **提示级** | 建议修改，不阻塞流程 | 在当前章节修复或在下一章注意 | 通用 advisory |

### 门控规则表

| 编号 | 检查项 | 级别 | 阈值 | 警示信号 |
|------|--------|------|------|----------|
| A | 逻辑连接词过载 | 🟡拦截 | >3次/300字 或 连续2章超标 | 然而/因此/此外/综上所述密度异常 |
| B | 情感标签词直写 | 🟡拦截 | ≥3处/章 直接使用情绪标签词 | 感动/愤怒/悲伤/孤独/温暖 直接出现 |
| C | 比喻密度超标 | 🟡拦截 | 像/仿佛/如同 >5次/章 | 常用比喻模式集中出现 |
| D | 段落长度均匀 | 🟡拦截 | 最长段/最短段比 <3:1 | 每段长度接近，缺乏变化 |
| E | 句式结构重复 | 🟡拦截 | 连续≥5句相同结构 | 主谓宾结构重复、句长接近 |
| F | 对话模板化 | 🟡拦截 | 角色对话去名后辨识度<70% | 每个角色说话方式无区别 |
| G | 开头平淡 | 🟡拦截 | 前50字无冲突/悬念/反转 | 天气/环境/背景介绍开场 |
| H | 无结尾钩子 | 🟡拦截 | 章末100字内无钩子信号 | 结尾无悬念/反转/危机 |
| I | 断更后风格断层 | 🔴回滚 | 停更后续写，角色语气/节奏偏离前章>30% | 前后章节如两人所写 |
| J | 叙事指纹偏离 | 🔴回滚 | 因果密度/句长方差偏离基线>2σ | 跨章节统计特征突变 |
| K | 情节逻辑断裂 | 🔴回滚 | 前章与本章因果链不连续 | 人物状态/战力/关系跳跃 |
| L | 设定吃书 | 🔴回滚 | 力量体系/世界观规则前后矛盾 | 同一设定在不同章节不一致 |
| M | 人设崩坏 | 🔴回滚 | 角色行为严重偏离性格设定 | OOC导致读者无法认同 |
| N | 文风一致性偏低 | 🟡拦截 | 连续多章风格偏离个人基线 | 前后章节如两人所写 |
| O | 字数不达标 | 🟢提示 | 偏离目标字数>20% | 番茄<1760字 起点<2400字 |
| P | 对话占比异常 | 🟢提示 | <25% 或 >55% | 过少则闷，过多则像剧本 |
| Q | 废笔不足 | 🟢提示 | 每500字<1处闲笔/走神细节 | 信息密度过高无留白 |
| R | 情绪曲线平直 | 🟢提示 | 连续3章无情绪起伏 | 全程高潮或全程平淡 |

### 毒句式欠账门（对标 oh-story-claudecode）

写下一章前自动扫描上一章正文，如命中以下**确定性格式**则阻塞下一章，直至修复：

```
欠账门命中列表：
├── 「不是A，是B」翻转句式（全家族）
├── ──「先否定再肯定」模板
├── 「首先…其次…最后」三段式
├── 「综上所述/总而言之」总结句式
├── 「值得一提的是/值得注意的是」填充句首
├── 句末「……”式升华结尾
├── 「不禁/不由/忍不住」情绪触发词
├── 「仿佛/好像」过度比喻
├── 情感标签直写（感动/愤怒/悲伤/孤独）
├── 预告式收尾（「接下来…」「后面将…」）
└── 工程词漏进正文（「本章/下一章/大纲」等）

豁免标记：在章节末尾添加 `<!-- 去味:跳过 -->` 可跳过欠账门检查
```

### 回滚流程

当触发🔴回滚级硬门时：

```
触发 → 自动诊断具体问题 → 提示用户 → 
├── 用户选择回滚到上一大纲节点
├── 修改后重新提交
└── 通过后清除回滚标记 → 继续下一章
```

## 附录G：反向指纹警告（过度自然度优化）

> 自然度优化不是越狠越好。过度自然度优化会产生"用力过猛"的痕迹——同样会损害阅读体验。

### 什么是反向指纹

当自然度优化清洗过度时，文本会呈现以下**反向AI特征**：

| 反向指纹 | 表现 | 成因 | 警示信号 |
|----------|------|------|----------|
| **电报体** | 句子过短(平均<12字)、段落破碎、无自然冗余 | 过度删除"废话" | 句长方差<0.3、自然度分降低 |
| **注水体** | 刻意加入的"的/了/就"等虚词密度超标 | 试图通过增加字数强行填充 | 虚词密度>8%，阅读体验明显下降 |
| **复读体** | "了一下/了半圈/了两下"等微动作高频重复 | 单一替换手法用太多 | micro-action-tic命中 |
| **套壳体** | 把原句套上"好像…一样""感到/觉得"等壳 | 试图掩盖句式模板特征 | 套壳句式占比>30% |

### 反向指纹避免原则

```
✅ 可以做的：
├── 打破均匀段落（从4句/段变成1-8句/段混排）
├── 替换AI高频词（用具体替代抽象）
├── 加入自然瑕疵（走神/留白/碎的对话）
└── 调整句长分布（短3字+长45字混排）

❌ 不可以做的：
├── 刻意注入语病（把"好"写成"还"之类的）
├── 有趣动词降级（"掏"改成"拿"——降级会损失表现力）
├── 全局补"的/了/就"（虚词超标是新指纹）
├── 每句都换行或变短（导致电报体）
└── 为追求形式牺牲阅读体验（平台要的是好内容，不是形式达标）
```

### "电报体"专项避免

过度自然度优化清洗最常见的后果是"电报体"——句子短、段落碎、无连接，读起来像在发电报。

**判断标准**：
- 平均句长<12字 → 电报体警戒线
- 1句段占比>30% → 需要加长部分段落
- 连续10段都是1-2句 → 明显电报体

**修复方法**：
- 将2-3个短句合并为一个中等长度的复合句
- 在断裂处加入自然的过渡细节（不是连接词，是动作/环境细节）
- 恢复部分"废笔"——并非所有废话都该删，自然冗余是人味的一部分

## 附录H：自进化自然度优化机制与动态黑名单

> 对标 NovelClaw 的 self-evolving anti-cliche system。系统每次发现新的模板化表达后自动学习，越用越精确。

### 动态黑名单机制

黑名单分为**静态库**（14大类固定词表）和**动态库**（每次检测后自动学习的新模式）：

| 库类型 | 来源 | 维护方式 | 示例 |
|--------|------|----------|------|
| **静态库** | 14大类预设词表 | 固定不变 | 然而/因此/综上所述 |
| **动态库** | 写作中新发现的模板化表达 | 每次自查后自动追加 | 用户特有的模式 |

### 自进化流程

```
写后自查 → 命中静态库规则 → 记录命中频率
         → 命中新发现模式 → 追加到动态库
         → 统计TOP命中项 → 调整自查权重
                           ↓
下一章写作 → 加载静态库+动态库 → 预防命中
```

### 动态黑名单管理

使用 `scripts/blacklist_manager.mjs` 管理（跨平台 Node.js）：

```text
# 查看当前黑名单统计
node scripts/blacklist_manager.mjs stats

# 查看TOP10高频命中词
node scripts/blacklist_manager.mjs top

# 手动添加新词到动态库
node scripts/blacklist_manager.mjs add "突然，他意识到"

# 重置动态库
node scripts/blacklist_manager.mjs reset

# 自进化（从最近扫描学习新AI模式）
node scripts/blacklist_manager.mjs evolve

# 导出黑名单（json/txt）
node scripts/blacklist_manager.mjs export json
```

### 自进化频率控制

| 阶段 | 动态库词数 | 严格度 | 适用场景 |
|------|-----------|--------|----------|
| 初始 | 0（仅静态库） | 标准 | 第一次使用 |
| 学习期 | 10-50词 | 较严格 | 使用3-5章后 |
| 成熟期 | 50-200词 | 严格 | 使用10章以上 |
| 自定义 | 用户设定 | 按需 | 有特殊需求 |

### 自适应阈值

系统根据动态库的词数自动调整自查严格度：

```
动态库词数 < 50  → 宽松模式（仅提示高频命中项）
动态库词数 50-100 → 标准模式（提示所有静态+动态命中）
动态库词数 > 100 → 严格模式（降低所有阈值20%）
```
